# Visual quieting — 결과와 출처의 위계

2026-09-09. 비교 기준 커밋: `7321e5f31d52dd7745d42884016cabe92501e643`.

결과를 먼저 읽고, 필요할 때 짧은 `ⓘ 출처`를 누르는 구성으로 정리했다. 노션 같은 관리 화면을 피하기 위해 검은 정체성 영역, 종이색 본문, 굵기의 차이가 있는 괘선, 방 번호, 기존 블랙레터를 사용했다. 새 장식·폰트·이미지·도메인은 추가하지 않았다.

## 1. 먼저 본 화면과 판단

변경 전 실제 앱에서 13개 화면을 360 / 1440 / 3440px로 캡처하고 39장을 읽은 뒤 [사전 위계 감사](VISUAL-HIERARCHY-AUDIT.md)를 작성했다. 변경 후에도 같은 화면과 폭의 39장을 확인했다. 별도로 네 방의 개요, 편집 화면, 펼친 카드 기록, 수동 표 선택 화면을 점검했다.

가장 복잡했던 곳은 펼친 방, 저장된 캐릭터의 상단, Reference Inspector였다. 방은 바깥 테두리 안에 검은 패킷과 필드가 중첩됐고, 캐릭터는 생성 설정이 이름보다 먼저 보였다. Inspector는 짧은 결과에도 출처·관련·표·상단 도구의 여백이 누적됐다. 이미 대부분 종이색인 UI였으므로 노란 박스를 무작정 제거하는 식으로 평가하지 않았다.

| 화면 | 먼저 읽을 것 · PRIMARY | 함께 읽을 것 · SECONDARY | 열어서 볼 것 · TERTIARY |
|---|---|---|---|
| Desk / Search | 검색, 일치하는 이름 | 직접 실행, 고정 | 최근, 전체 색인, 지역 |
| Oracle | 방금 나온 결과 | 재굴림, 복사, 짧은 한국어 | 출처, 관련, 카드 기록 |
| Rule / Power | 이름과 실제 작동 규칙 | 필요한 DR·주사위·한국어 | 출처, 관련 |
| Dungeon | 던전 이름 | 개요 묶음, 네 방 | 상태, 전체 재굴림, 메모 |
| Room | 번호, 원문 구성 요소 | 독립 재굴림, 복사 | 편집, 번역 펼침, 출처, 순서·삭제 |
| Character | 이름과 Class | HP·Omens·능력치·장비 | 생성 설정, 자세한 Class, 관리 |
| Monster / NPC / Encounter | 이름과 실제 결과 | 전투 수치·공격·필수 특징 | 생성 설정, 배치, 메모, 출처 |
| Table | 항목과 주사위 범위 | 현재 결과, 수동 선택 | 추가 효과, 출처 |
| Source | 책·쪽과 출처 역할 | 표 링크, 굴림 | 정책·전체 출처 정보 |

강도는 검색·표·출처 LOW, Dungeon·Character·Monster MEDIUM, Oracle 결과 HIGH로 두었다. 모든 화면을 같은 카드 템플릿으로 만들지 않았다.

## 2. 화면별 변경

### Reference Desk와 검색

- 검은 검색창과 한 줄의 산성 노란 괘선이 첫 시선을 받는다. 두꺼운 외곽 상자는 제거했다.
- Pinned / Recent를 카드나 좌우의 동등한 큰 섹션 대신 짧은 가로 바로 압축했다. 원클릭 실행은 유지한다.
- 검색 행은 이름과 종류·책의 두 줄이다. 닫힌 검색 행의 중복 한국어 제목만 숨겼다. 열린 규칙과 결과의 한국어 도움말은 유지했다.
- Quick Tools는 데스크톱에서 네 개의 짧은 열, 360px에서는 읽을 수 있는 한 열이다. 새 링크나 검색 순위 변경은 없다.
- 지역과 전체 색인은 더 조용한 인덱스가 된다. 캠페인·세션 선택 없이 Desk를 사용한다.

### Inspector / 출처 / 자세히

- 반복되던 `SOURCE · HOW GENERATED`, 긴 한국어 출처 설명 등을 보이는 곳에서는 **`ⓘ 출처`**로 통일했다. 맥락은 접근성 이름에 남겼다.
- `MORE · 자세히 ›`는 **`자세히`**, 상세 편집은 **`자세히 · 편집`**, 표는 **`표 보기`**, Related는 **`관련`**이다.
- 창 안의 상단 도구도 `검색 / 최근 / 고정`으로 짧게 표시한다.
- 짧은 Oracle은 도구 이름보다 굴린 단어가 크게 보인다. 공유 Inspector의 불필요한 간격을 줄였고 기존 780px 최대 폭을 유지했다.
- Source는 바로 한 번 눌러 여는 닫힌 disclosure다. 흰 내부 상자와 왼쪽 굵은 선을 제거하고 책/표 링크를 간결하게 배치했다.
- PRIMARY SOURCE / ROUTING SOURCE / SOURCE PROCEDURE / APP POLICY, 수동 편집 표시, 책·페이지·굴림은 그대로 보존했다. 경고는 경고일 때만 표시한다.
- Source나 Table이 추가 모달을 쌓지 않으며, 닫으면 기존 방과 스크롤 위치로 돌아간다.

### Table / 절차

- 기존 Table CSS의 중복된 기본 선언을 한곳으로 합쳤다. 범위 열을 확보해 `9–10`, `11–12`가 쪼개지지 않는다. 얇은 선과 현재 행 강조만 남겼다.
- 기존 `USE THIS RESULT` 동작·조건·목적지는 그대로다. 360 / 1440px에서 Weapons 항목 선택, APP POLICY 표시, 표 복귀, 저장 없음까지 확인했다.
- RECLVSE의 필수 판정·결과는 숨기지 않고 문단 간격만 줄였다. 줄어든 화면 안에서 더 많은 작동 규칙을 읽는다.
- Depths 희귀 몬스터는 **생성 결과 → DRAW / COPY → 카드 기록 → 절차** 순서다. 카드는 닫힌 기록 안의 작은 3열 구조로 보이며, 순위·무늬·조건부 추가 카드와 새 덱 동작은 그대로다.
- City / Travel / Mythic의 정의와 다음 절차 관계는 바꾸지 않았다. 공통 Inspector의 여백·레이블·출처 표현이 적용된다.

### Dungeon / Room

- Dungeon은 이름 다음에 큰 개념 묶음이 이어지는 문서 구성이다. 개요 필드마다 동일한 경계를 두지 않는다.
- 전체 재굴림은 기존 편집 헤더 옆 `⋯`에 둔다. 기존 확인문구와 실행 코드는 유지한다.
- Room의 외곽 상자 안에 검은 상자가 들어가던 중첩을 없앴다. 네 방은 번호와 원문 파편을 읽는 dungeon key처럼 보인다.
- 펼친 방은 전체 폭을 사용한다. 중복 방 번호를 줄이고, 라벨보다 실제 결과를 크게 했다. 독립 요소 재굴림은 직접 누른다.
- 네 방의 순서 버튼 8개를 `⋯` 4개로 접었다. 삭제도 `방 관리` 아래에 둔다. 메모 입력은 의도적으로 열 때 보인다.
- 구성 요소·재굴림 의존성·출처·수동 편집·안정적인 ID는 그대로다.

### Character / Monster / NPC / Encounter

- 저장된 Character는 생성 설정이 닫혀 있고 `편집`을 누르면 다시 나타난다. 새 초안에는 생성 설정이 바로 보인다.
- 검은 이름 영역과 가는 마젠타 선은 남겼다. 능력치와 장비는 종이색으로 읽으며, 과한 높이를 만들던 number-field 최소 높이를 정리했다.
- Monster는 이름·HP / Morale / Armor·Attack이 먼저다. 저장된 Monster의 전체 재굴림과 생성 설정은 상세 편집 안에 있다. 새로 생성 중인 후보의 재굴림은 바로 누를 수 있다. Source는 계속 직접 접근한다.
- NPC / Encounter는 따로 있던 생성 설정을 기존 편집 disclosure에 합쳤다. 긴 상세 레이블을 줄이고 좁은 화면의 생성 버튼을 과도한 전폭 막대로 만들지 않는다.
- 상태·배치·세션 연결 같은 관리 기능은 `상태 · 배치`로 접었다. 기존 Context Quick Tools는 유지한다.

### Navigation / 색과 타입

- 사이드바의 반복 아이콘을 숨기고 텍스트·선택 표시로 구분한다. 보조 기록은 기존처럼 닫힌다.
- FATE의 영구 노란 배경과 하단 Reference Dock의 노란 그림자를 없앴다. 브랜드, 검색 괘선, 실제 선택/결과의 강조는 남겼다.
- 일반 primary 버튼은 검정/종이색으로 읽는다. 기존 heading 버튼 선택자의 우선순위 때문에 생성 후보의 저장 버튼이 종이 위 노란 글자가 되던 문제도 수정했다. hover 강조와 비활성 상태는 구분한다.
- 마젠타는 캐릭터 정체성의 얇은 강조로 남겼고 모든 입력의 기본 포커스 색으로 쓰지 않는다.
- 기존 display / reading / UI / mono 역할을 사용한다. Source는 기술적인 작은 활자, 실제 결과는 강한 활자다. 새 폰트·장식·랜덤 배치는 없다.
- 상단 바 기능과 FATE / Dock 자체는 유지한다. 반복 출처를 빼기 위해 실제 저장 텍스트를 가공하지 않았다.

## 3. 전후 수치

1440 × 1000, 같은 저장된 QA 객체와 같은 참조 화면. 단위는 px. `강한 경계`는 3면 이상 2px 이상인 컨테이너, `노란 면`은 500px² 이상인 단색 배경이다. 노란 글자·그림자·가는 선은 이 숫자에 들어가지 않는다. 전체 문서 높이와 Inspector 내부 길이는 별도다.

중요한 해석: **모든 화면의 보이는 버튼 수가 줄었다고 주장하지 않는다.** 검색은 같은 높이 안에 더 많은 실행 행이 들어오면서 30→46개가 보인다. RECLVSE와 카드 창도 아래에 있던 유용한 도구가 위로 들어온다. 기능 수 증가가 아니다. Room 순서·생성 설정·배치 같은 낮은 빈도의 관리 노출은 줄었다. 기존 화면에 강한 사각형이 수십 개 있었다는 과장도 하지 않는다.

페이지 높이 감소는 콘텐츠 삭제가 아니라 생성 설정·중복 상자·여백을 접고 정리한 결과다. 무작위 결과의 글자 길이는 매번 같지 않을 수 있다. QA seed도 React/브라우저 호출에 소비될 수 있으므로 결과가 완전히 동일한 난수였다고 간주하지 않는다. 저장된 Character/Dungeon/Room/라이브러리 객체는 동일한 fixture로 비교했다.

## 4. 클릭 비용과 실제 브라우저

| 관련 맥락에서 하는 일 | 이전 | 이후 |
|---|---:|---:|
| 검색 결과 → Reaction 굴림 | 1 | 1 |
| Pin → 실행 | 1 | 1 |
| Recent → 실행 | 1 | 1 |
| Character 무기 / Power → 정의 | 1 | 1 |
| 펼친 Room 구성 요소 → 재굴림 | 1 | 1 |
| Room → Source | 1 | 1 |
| Monster → Source | 1 | 1 |
| 결과 복사 | 1 | 1 |
| Dungeon → 방 탭 → Room 02 | 2 | 2 |
| 희귀 몬스터 → 사용한 카드 기록 | 0 | 1 |

전체 비교 시나리오는 이전 프로덕션 **51클릭 / 검색 입력 5회**, 이후 데스크톱 **52클릭 / 검색 입력 5회**다. 추가 한 번은 사용한 카드 기록을 의도적으로 여는 단계다. 360px에서는 **57클릭**으로, 데스크톱과 같은 흐름에 메뉴 열기 5회가 더해진다. 이 세션에는 비교용 추가 표·Source·편집·재접속 검사도 포함했다. 스크롤, 키보드, 새로고침은 클릭 수에 포함하지 않고 별도 검사한다.

실행한 연속 흐름:

1. Reaction 직접 굴림 → COPY → Source → Table → 결과 → COPY WITH SOURCE.
2. Broken / Daemon of Capillaries → 실제 규칙과 한국어 확인.
3. QA Character → 무기 → 복귀 → 실제 보유 Power → 복귀 → 편집/읽기 전환.
4. Dungeon 개요의 네 방 → Room 02 → 독립 요소 재굴림 → Source → 원문 표 → 방과 스크롤 위치 복귀 → 편집/읽기 전환.
5. 저장 Monster → Source → 라이브러리에서 새 Monster → 특수/상세.
6. Desk → Action + Theme → Pin → 원클릭 Pin / Recent 실행.
7. 희귀 몬스터 → 사용 카드 확인 → 새로고침 → 캠페인·고정 보존 → Ctrl+K / Enter / Escape.

이후 두 폭에서 각각 **26개 브라우저 검사 통과**, 오류 0. 일반 Copy에 내부 ID/출처가 들어가지 않고, Copy with Source에 간결한 출처가 남는다. 표·방 전환 중 겹친 대화상자나 맥락 유실이 없었다. Room ID/무관한 요소가 보존되고, 새로고침 후 변경한 QA 결과와 고정이 유지됐다. 사용자의 브라우저 프로필과 실제 캠페인은 쓰지 않았다. 의도적 QA 재굴림/초안 외에 저장된 Character / Monster / NPC / Encounter와 나머지 방이 변하지 않았음을 비교했다.

덜 자주 쓰는 저장 객체의 전체 재굴림·순서·삭제·상태 수정에는 disclosure를 여는 한 번이 추가된다. 생성 후보의 재굴림, 매번 쓰는 결과 굴림·요소 재굴림·정의 링크·출처를 그 뒤로 숨기지는 않았다.

## 5. 반응형·접근성·실제 이미지

- 13종 × 3폭의 변경 후 캡처에서 가로 overflow 0, 브라우저 오류 0. 3440에서는 콘텐츠 폭을 제한해 장비·결과가 화면 전체로 늘어나지 않는다.
- 360에서는 긴 카드 결과의 한국어를 별도 작은 줄에 두어 제목과 경쟁하거나 이상하게 꺾이지 않게 했다. 카드 기록은 3열과 다음 줄로 이어진다.
- Room을 한 열로 펼쳐 필드 안의 필드처럼 보이던 폭 손실을 줄였다. 네 방의 개요도 따로 확인했다.
- 짧은 출처 글자와 클릭 영역은 다르다. 측정한 Source / Room Source / 요소 재굴림은 모두 **44×44**, Copy는 **76×44**다. 기존 일반 Source의 36px 높이도 44px로 보완했다.
- native details/summary와 이름 있는 button을 유지했다. 아이콘만의 정보에 의존하지 않고, 포커스는 대비가 있는 2px 윤곽선이다. 기존 reduced-motion 처리는 유지했다.
- 표의 주사위 구간을 읽을 수 있고, 손으로 선택하는 버튼도 모바일에서 노출된다. 수동 선택이 가짜 굴림이나 캠페인 저장으로 바뀌지 않는다.

이미지 위치: `outputs/visual-quieting/before/`와 `after/`의 `{surface}-{360|1440|3440}.png`. 화면명은 사전 감사 및 metrics JSON에 있다. 추가 실제 흐름은 `acceptance-after-1440/`, `acceptance-after-360/`, `table-use/`에 있다. 이미지의 출처/저장 결과가 불필요하게 공개 저장소에 들어가지 않도록 PNG는 로컬 QA 출력으로 남기고, 도구·수치·검사 기록을 커밋한다.

## 6. 변경 경계와 검증

생산 변경은 React 표현 컴포넌트와 기존 `reference.css`, `workspace.css`, `art-direction.css` 소유 영역이다. 새 disclosure/wrapper에 필요한 선택자 외에 새 스타일 계층을 만들지 않았다. 중복된 기본 Table 선언, 이전 검은 Room 배경을 전제한 밝은 경고 스타일, 무효한 빈 선언과 새로 끼어든 불필요한 공백을 정리했다. 전체 CSS 재작성은 하지 않았다.

도메인, 생성기, 원문 데이터, 소스 로딩, 검색/관계, schema, import/export, 저장 정책과 ID를 변경하지 않았다. 기존 이동·삭제·재굴림 핸들러와 확인 조건은 그대로 위치만 옮겼다. Source 내부의 신뢰도·권위 분류도 바꾸지 않았다.

- 기존 **653개 + 신규 5개 = 658개 테스트 통과**, 실패/skip 0.
- 신규 검사는 짧은 Source의 접근성 이름/실제 출처, 저장 Character와 초안의 표시 차이/무변경, 접힌 상태·배치 제어, Dungeon 헤더 관리/원래 필드 보존, 새 Monster 후보의 직접 재굴림과 저장 Monster 상세 편집의 구분이다.
- 기존 두 테스트는 보이는 `SOURCE` / `EDIT` 레이블의 기대값만 변경했다. 기능·원문/출처 검증을 약화하지 않았다.
- `npm run lint` 통과.
- `npm run build`의 앱/서버 TypeScript, Vite, 공개 빌드 privacy 검사 통과(74 static files).
- 기존 10,000회 rare monster 및 generator/source 무결성 검사도 전체 suite에 포함되어 통과했다. 새 콘텐츠 없음, UNSOURCED 검증 유지.
- 독립 UI 검사: 실제 세션 26개 × 데스크톱/모바일, 수동 표 선택 두 폭, 39개 후속 화면 캡처. 이를 unit test 수에 합쳐 과장하지 않는다.

재현 자료: `before-metrics.json`, `after-metrics.json`, `acceptance-before-1440.json`, `acceptance-after-1440.json`, `acceptance-after-360.json`, `table-use-acceptance.json`, `tools/`.

## 7. 남은 시각적 마찰 / 배포 경계

- 길고 중요한 영문/한국어 절차는 여전히 세로로 스크롤한다. 작동 규칙을 숨기거나 줄여서 높이를 맞추지 않았다.
- 일부 기존 저장 Encounter 문자열에는 출처가 문장 자체에 들어 있다. 저장 결과를 재작성하지 않는 범위라 그대로 보존했다.
- 모바일에는 Reference Dock과 FATE 도구가 모두 남는다. 고정 항목이 늘어날 때 충돌하지 않도록 기존 별도 위치를 유지했다. 상단의 긴 고정 목록은 가로로 스크롤한다.
- 열린 Source에서 현재 표 보기와 개별 source table 링크가 함께 보일 수 있다. 서로 다른 경로/맥락을 유지하며 기본 결과에는 노출하지 않는다.
- 길이가 다른 실제 결과에 맞춰 페이지 길이가 달라진다. 모든 화면을 같은 높이로 만들지 않았다.

이 문서의 결과는 검증된 로컬 프로덕션 빌드 기준이다. 정확한 전달 커밋과 실제 공개 배포 확인은 완료 메시지에서 별도로 보고한다. 로컬 스크린샷을 공개 배포의 증거로 간주하지 않는다.
