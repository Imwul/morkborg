# Character 생성·저장 및 서체 검증

2026-09-03. 기존 Campaign → Dungeon → Room 생성·저장 구조 위에 Character Library와 편집기를 추가했습니다. Monster/NPC/Encounter 생성, 배치, 전투, 성장, 인증, 동기화 기능은 이번 단계에서 추가하지 않았습니다.

## 데이터 모델

`Character`는 UUID `id`, 소속 `campaignId`, `name`, `className`, 선택 `classSource`, 현재 `hp`, `maxHp`, 네 능력치, `omens`, `silver`, `armor`, `description`, `status: 'alive' | 'dead'`, 독립 `notes`, 생성/수정 시각과 출처를 가집니다.

`weapons[]`, `equipment[]`, `traits[]`는 각각 UUID를 갖는 구조화된 항목입니다. 항목은 `text`, 선택 `source / tableId / slot`을 가지며 무기는 `damage`도 분리합니다. 번호는 표시용입니다. 목록을 삭제하거나 순서를 바꾸더라도 UUID로 다른 항목을 구분할 수 있습니다.

Campaign의 `characters[]`는 저장한 캐릭터, `drafts.characters`는 저장 전 후보입니다. 새 캐릭터 버튼은 남아 있는 후보가 있으면 이어서 엽니다. 후보를 다른 화면 이동이나 새로고침 때문에 새로 생성하지 않습니다. 저장된 캐릭터도 같은 편집기에서 계속 수정합니다. 0 HP로 상태를 자동 변경하지 않습니다.

## 사용한 실제 표와 규칙

아래 페이지는 사용자가 제공한 **MÖRK BORG BARE BONES EDITION PDF**의 페이지 번호입니다. 정규판의 해당 Character Creation 페이지도 대조했습니다.

| 항목          | 실제 규칙 / 표                        | PDF 페이지 |
| ------------- | ------------------------------------- | ---------- |
| 이름          | d6×d8의 48개 이름, 동등한 균등 선택   | 2          |
| 능력치        | 각각 3d6을 −3~+3 보정치로 변환        | 27         |
| HP            | `max(1, Toughness + d8)`              | 29         |
| Omens         | Classless d2, 선택 규칙               | 37         |
| 은화          | 2d6×10                                | 21         |
| 기본 장비     | Waterskin, d4일 식량, 운반수단 d6     | 21         |
| 기타 장비     | gearA와 gearB의 d12 표를 각각 한 번   | 22         |
| 무기 / 방어구 | d10 / d4, 시작 scroll 보유 시 d6 / d2 | 23         |
| Scroll 내용   | 실제 sacred / unclean 표와 효과       | 34–35      |
| 성향          | Terrible Traits d20 두 번             | 38         |
| 외형          | Broken Bodies d20 한 번               | 39         |

생성 순서는 능력치 → HP·자원 → 장비 → scroll 확인 → 무기·방어구 → 성향·외형입니다. Presence 기반 수량, 약물 용량, 동물 HP도 기존 원문의 계산을 유지합니다. 중복 성향을 인위적으로 제거하지 않습니다. 캐릭터에 지역 가중치를 적용하지 않습니다.

Classless를 명시적으로 생성합니다. 여섯 기본 직업은 능력 주사위뿐 아니라 출신·특수 항목·장비 예외를 함께 적용해야 하며 현재 자료 팩에 완전한 클래스 표가 없습니다. 클래스 이름만 무작위로 붙여 완성된 클래스 캐릭터로 제시하지 않습니다. 직업명을 직접 입력할 수 있으며 Classless가 아니면 이름·특성 외의 자동 재굴림을 비활성화합니다. 클래스 특수 능력과 4d6 최저 제외 선택 규칙은 자동화하지 않았습니다.

## 개별 재굴림과 직접 작성

- 이름, 각 능력치, 능력치 전체, HP, Omens, 은화, 방어구, 무기별, 장비 슬롯별, 특성별 재굴림을 제공합니다.
- HP 재굴림은 현재 Toughness로 최대 HP와 현재 HP를 함께 정합니다. 별도 확인창에 이 범위를 명시합니다.
- 자동 최대 HP는 최초 d8 결과를 저장하여 Toughness 변경 시 같은 d8로 다시 계산합니다. 직접 입력한 최대 HP는 이 자동 연동을 끕니다. 직접 입력한 현재 HP도 보존합니다.
- 다른 슬롯의 재굴림은 수동 입력을 바꾸지 않습니다. 장비 슬롯만 굴릴 때 기존 무기·방어구가 scroll 시작 조건에 맞지 않으면 scroll 항목만 제외하고 나머지 원래 가중치를 유지합니다. 이 조정은 출처에도 표시합니다.
- 고정 Waterskin, 구형 통합 장비, 수동 추가한 장비에는 근거 없는 무작위 표를 붙이지 않습니다. 모두 직접 수정할 수 있습니다.
- 전체 캐릭터 재굴림은 확인 후 수행합니다. 생성값을 Classless로 새로 만들고 캐릭터 UUID·생존 상태·Notes를 유지합니다.
- 숫자는 유한한 정수와 필드별 범위로 검증합니다. 현재 HP와 최대 HP를 독립적으로 직접 수정할 수 있습니다.

## v2 → v3 저장과 JSON

현재 저장 키는 `morkborg-codex:v3`, `schemaVersion: 3`입니다. 로드 순서는 v3 → v2 → v1이며 이전 버전을 모두 합쳐 중복 생성하지 않습니다. 변환 전 원문 문자열을 `morkborg-codex:pre-v3-backup`에 먼저 보관한 다음 v3를 씁니다. v2·v1 원본 키와 기존 pre-v2 백업은 그대로 남습니다.

구형 Character는 `archetype → className`, 소속 Campaign의 ID → `campaignId`, `Alive/Dead → alive/dead`로 옮깁니다. `hp`는 음수와 0도 그대로 보존합니다. 구형 저장에는 최대 HP가 없으므로 `max(1, 기존 hp)`로 임시 초기화하며, **최대 HP를 직접 확인해야 한다는 출처**를 표시합니다. 기존 무기·장비 문자열은 세미콜론이나 줄바꿈으로 임의 분할하지 않고 항목 하나의 원문으로 보존합니다. 기존 묘사는 `description`에 그대로 남습니다. 미저장 캐릭터 초안과 선택 ID도 변환합니다.

Campaign JSON은 모든 캐릭터와 항목, 현재/최대 HP, 생존 상태, Notes, 출처, 초안을 포함합니다. v1·v2 JSON도 변환해 읽습니다. 기존 소유 UUID와 충돌하면 Campaign·Character·항목·Dungeon·Room과 내부 참조를 함께 새 UUID로 복제합니다. 원본 Campaign을 덮어쓰지 않습니다. 캐릭터 단독 복제도 새로운 ID·생성 시각·독립적인 항목을 가집니다.

## 자동 검사

기존 29개 행동 검사를 유지했습니다. 스키마 버전 기대값과 새 장비 배열·소속 Campaign 검사에 맞춰 두 기존 테스트 파일을 조정했으며, 검사 범위는 줄이지 않았습니다. `tests/characters.test.ts`의 17개를 더해 **총 46개 통과**했습니다.

신규 검사는 v2 원문/초안 변환, 음수·0 HP와 명시 상태, 누락/손상 라이브러리, 백업·저장 실패, Classless 생성, 정확한 후보 저장, UUID 삭제, 독립 복제, 개별 재굴림과 수동값 보존, 현재/최대 HP 분리, Toughness 연동, 유효하지 않은 숫자, 장비 제한, Notes 분리와 재로드, JSON 충돌 가져오기, 120개 캐릭터 및 항목 ID/소속 검증을 다룹니다. TypeScript·프로덕션 빌드·린트도 통과했습니다.

## 실제 UI의 27단계

Codex 내장 브라우저의 로컬 앱에서 실행했습니다. 대상은 기존의 설명이 `Campaign v2 acceptance — two independent dungeons`인 **THE ASHEN PSALM**입니다. 검증 전 Campaign JSON을 UI에서 읽어 비교 기준으로 보관했습니다.

| 단계  | 결과                                                                                                                                            |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 1–2   | 기존 Campaign을 열었습니다. `The Slave waste` / Graven-Tosk와 `The Plague church` / Sarkash, 각각 방 4개가 남아 있었습니다.                     |
| 3–4   | 캐릭터 보관함의 빈 상태에서 새 캐릭터를 생성했습니다. 저장 전 후보로 표시되었습니다.                                                            |

| 7     | 특성 1만 재굴림했습니다. 해당 필드 한 곳만 변경되었습니다.                                                                                      |
| 8–10  | 현재 HP 5 / 최대 HP 8, 이름 `Hervör — Kergüs`, 한글 두 줄의 개인 Notes를 직접 입력했습니다.                                                     |

| 21–23 | 브라우저 reload 후 두 캐릭터가 남았고 4/8·사망·이름·Notes가 유지됐습니다. 두 던전 전체도 시작 전 JSON과 일치했습니다.                           |

이번 UI Export/Import는 JSON 표시 창·붙여넣기 경로로 검증했습니다. 운영체제의 파일 다운로드 완료 이벤트는 별도로 검증하지 않았습니다. 검증 원본 Campaign, 복제본, 가져온 Campaign은 남겨 두었습니다.

## 서체와 반응형 화면

기존 Black Han Sans와 NanumSquare Neo에는 ö ä ü ú Ä Ö Ü 및 결합 악센트 U+0308/U+0301 글리프가 없었습니다. **Barlow Condensed Black 900 + Pretendard Variable**의 공식 원본 파일과 OFL을 로컬에 포함했습니다. 새 두 폰트의 cmap에서 해당 문자와 결합 악센트 지원을 직접 확인했습니다. 원문 철자를 바꾸거나 악센트를 제거하지 않습니다.

UI의 제목·입력·카드에서 `Hervör — Kergüs`, 본문에서 `MÖRK BORG · Wästland · Kergüs · Sigfúm · Hervör`와 NFD `Mörk · Wästland`를 확인했습니다. 360px에서 모두 정상 표시되었습니다.

| 화면 폭 | 문서 scrollWidth | 캐릭터 주요 정보 / 항목 열 |
| ------- | ---------------- | -------------------------- |
| 360     | 345              | 1 / 1                      |
| 768     | 753              | 1 / 1                      |
| 1440    | 1425             | 2 / 2                      |
| 3440    | 3425             | 3 / 3                      |

네 폭 모두 가로 overflow가 없었습니다. 360px 숫자 입력 폭은 305px, 개별 재굴림 버튼은 최소 36px이며 장비·묘사 textarea의 내부 가로 overflow도 없었습니다. 사망 카드는 흐리게 숨기지 않고 읽을 수 있는 텍스트와 상태 표시로 구분합니다. 기존 던전 개요의 3440px 4열 배치와 한글 행간은 유지합니다.

확인된 기능 blocker는 없습니다. 선택 직업의 특수 규칙 자동화와 과거 최대 HP의 정확한 추론은 제공하지 않습니다. GitHub 인증/쓰기 권한 상태는 로컬 구현·검증 성공과 별도로 보고합니다.
