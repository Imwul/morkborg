# 룰북 반영·플레이 흐름 개선 결정 기록

2026-10-03 · 기준 커밋 `e67fb8d` · 대상: 기존 디자인 씽킹 감사의 **1–21번**

사용자가 1–21번을 파티모드로 자율 진행하도록 승인했다. 기존 BMAD Party Mode의 installed 파티를 사용해 사용자 경험(Maya), 원인·출처 정확성(Dr. Quinn), 시각적 위계(Caravaggio), 플레이의 이야기 흐름(Sophia), 우선순위(Victor), 대안 탐색(Carson)의 관점을 비교했다. 추가 사용자 인터뷰나 별도의 사용자 실험을 했다고 간주하지 않았다.

## 판단 기준

PC에서 책·종이 노트 옆에 두고 쓰는 솔로 플레이 도구다. 영어를 먼저 읽고 한국어를 보조로 사용하며, 결과를 종이에 옮긴다. 따라서 생성 결과의 완전성과 원문으로 이어지는 연결을 우선했다. HP, 방어구 손상, 반복 재앙의 지속 피해는 사용자가 처리한다.

기존 헤더, Space Mono 숫자, 노란색·검정·종이의 MÖRK BORG 톤, 홈의 일곱 빠른 참조를 유지했다. 오른쪽 아래 도구는 비모달로 유지하고 접기 기능은 추가하지 않았다.

## 같은 날의 후속 결정: 캐릭터 생성 방식

사용자가 직업 선택 버튼의 누락을 지적했고, **룰북 / SCVMBIRTHER 구분을 Classless / Random Class / Choose Class로 대체**하도록 지시했다. 이 후속 지시는 1번 항목의 외부 생성기 선택 유지 결정에 우선한다.

- **Classless:** 기존 완성 PC 생성과 능력치 4d6 선택 규칙을 유지한다. 선택적인 Omens의 표시를 `Use Omens · 시작 1–2점`으로 명확히 했다.
- **Random Class:** 검증된 생성 절차가 있는 Core 6개·FERETORY 4개·HERETIC 2개, 총 12개 중 같은 확률로 선택한다. 여러 책을 합친 직업 선택 확률은 앱의 구성으로 명시하며 원문의 단일 주사위로 표시하지 않는다.
- **Choose Class:** 같은 12개를 책별 목록에서 선택한다. 기존 직업 엔진의 능력치 보정, HP, 은화, Omens, 방어구·두루마리 제약, 배경, 고정 규칙과 직업 능력을 사용한다. RCL 6개 직업은 여전히 읽기 전용이다.
- **결과를 유지:** 버튼이나 직업 목록을 바꾸는 것만으로 재굴림하지 않는다. 다음 ROLL / REROLL에 적용하며, 최근 굴림에는 방식과 확정된 직업을 함께 기록한다. 기존 SCVMBIRTHER 결과의 출처·보관함 기록은 유지한다.

직업별 참조만 추가하는 대안은 실제 캐릭터 생성의 누락을 해결하지 못하므로 제외했다. 화면에 원문 제공자 선택을 남기는 대안도 사용자가 지정한 세 가지 구분과 맞지 않아 제외했다.

## 이번 토의에서 정한 경계

- **수동 처리를 유지:** HP, 방어구 손상, 재앙 반복 여부·지속 피해, 사냥 성공 여부는 자동 확정하지 않는다.
- **기본값을 조용히 확장하지 않기:** 4d6 능력치, Core Omens, Orakle DR, 준비된 모험, EPK 확장 주사위는 사용자가 선택한다.
- **동명 자료를 합치지 않기:** Core/RCL 주문, Pale One 직업/동행 생물은 출처 ID로 구별한다. 기존 생성 문장의 연결을 보존하면서 별도 검색 결과도 제공한다.
- **미지원 생성 절차를 만들지 않기:** RCL 직업은 읽기 전용이다. 완성 생성기는 기존 지원 직업과 Core Classless 범위다.
- **제외 자료를 복구하지 않기:** 이전에 제거한 시나리오 전용 표는 복구하지 않았다. FER의 시나리오 전용 minor/major treasure 표도 해당 정책을 따른다.
- **22–24번은 범위 밖:** Mythic Thread Progress, Peril Points, Chaos/Fate 변형은 이번 구현에 포함하지 않았다.

## 원문·구현 근거

원문 PDF의 위치와 SHA256은 기존 `docs/pdf-escape-audit/data/source-inventory.json`을 사용했다. RCL Relics는 두 열을 분리해 읽었고, RCL 직업의 고정 능력은 무작위 표가 시작되기 전의 영역을 대조했다. Nesting Death는 Core Full의 독립 기록이며 Wild Wickhead 등 다른 생물로 대체하지 않았다.

`scripts/enrich-rule-fidelity.py`는 개인 원문 자료의 해당 투영을 재생성한다. `scripts/attest-rule-fidelity.ts`는 대조한 9개 표와 추가 생물의 지문을 기록한다. `scripts/publish-private-update.mjs`는 기존 키를 유지해 암호화된 갱신만 발행한다. 평문 룰북·번역·키는 Git에 추가하지 않는다.

과거 공간 탐색 감사의 기준 파일은 그대로 두었다. 이번 확장 기준은 `registry-baseline.json`에 별도로 남긴다. 표 548개, 절차 64개, 참조 1,180개, 표의 행 12,328개, 원문 생물 기록 90개다. 늘어난 수와 해시를 검사에 반영하되, 원문 구간·주사위·출처 검증과 탐색 전후 데이터 불변성 검사는 유지했다. 기존 Core 주문 20개·직업 6개에 대한 검사는 해당 책의 범위로 명확히 한정했다.

이번 작업은 감사 목록 1–21번의 수정이며, 모든 룰북 전 페이지의 완전성 인증은 아니다.

## 반영 기록

이 변경은 `main`에 커밋하고 `origin/main`으로 푸시한다. 선택한 안과 제외한 대안은 이 문서의 21개 항목을 기준으로 한다.

검사를 마친 production 산출물을 기존 개인 서버의 `dist`에 반영했다. 열린 화면이 이전 파일을 요구할 수 있어 이전 해시의 자산도 보존했다. 기존 서버는 파일을 요청할 때 다시 읽으므로 서버를 재시작하거나 빌드를 다시 실행하지 않았다. 기존 암호화 키를 유지하고 새로운 개인 자료 갱신 묶음만 반영했다.

검사용으로 임시 연결했던 의존성은 작업 전의 `node_modules`로 복원했다. 사용자의 기존 BMAD 자료와 관련 없는 미추적 문서는 커밋에 추가하지 않는다.

캐릭터 생성 방식의 후속 수정은 12종 직업별 생성·보관·재굴림 기록과 기존 생성기를 포함한 집중 검사 118개로 확인했다. 최종 수정 뒤 클라이언트·서버 TypeScript 검사, production 빌드, lint와 공개 빌드·개인 자료 경계 검사도 통과했다. 브라우저에서 세 방식의 전환, 현재 결과 유지, 다음 재굴림 적용, Classless의 선택 규칙 표시를 확인했다. 개인 원문 자료를 변경하지 않아 추가 자료 갱신은 발행하지 않았다.
