## 생성 후보 및 한글 화면 개선

같은 날 추가 확인했습니다.

- 제목을 입력하지 않고 생성기를 열면 개요 11개와 방 네 개를 갖춘 후보가 나타남을 확인했습니다. 반복 재굴림 중에는 저장된 던전 수가 늘어나지 않습니다.
- 입구와 제목을 각각 재굴린 전후의 화면 값을 비교하여, 대상 한 항목만 달라졌음을 확인했습니다.
- 직접 작성 모드의 빈 후보에서 제목과 입구를 쓰고 다른 항목을 굴려도 수동 입력이 유지되었습니다. 방 하나의 위험 / 함정만 굴렸을 때 다른 방과 개요 값은 그대로였습니다.
- 한글 두 줄의 직접 입력과 후보 메모가 다른 화면 이동 및 새로고침 후 그대로 복원되었습니다.
- 선택 전후의 캠페인 내보내기 JSON을 비교했습니다. 저장 시각을 제외한 후보의 내용·출처·UUID·방 네 개의 데이터가 모두 일치했고, 기존 던전은 바뀌지 않았습니다. 검증용으로 저장한 던전은 확인 후 삭제했습니다.
- 3440×1440에서 콘텐츠 영역 약 3145px, 개요 네 열을 확인했습니다. 1920×1080에서 두 열, 360×800에서 한 열이며 문서 가로 넘침이 없습니다. 한글 제목의 Black Han Sans와 본문의 나눔스퀘어 네오, 넓힌 행간을 화면으로 확인했습니다.
- 자료 로드 요청 중복·가져오기 경합과 HMR 복원을 보완했습니다. 자료가 준비되면 기다리던 첫 후보를 만들고, 이미 직접 작성하거나 편집한 후보는 유지합니다.
- PDF 표 제목이 보물 결과에 포함된 추출 오류를 교정했습니다. 실제 결과 열 개 및 올바른 가중치를 검사합니다.

TypeScript·프로덕션 빌드·린트가 통과했습니다. 개인 자료가 있는 작업 환경에서 자동 검사 17개가 모두 통과했으며, 새 검사는 후보 생성·선택·복제·JSON 복원 및 자료 로딩 경합을 다룹니다.

| 12   | 두 번째 새 던전 흐름을 열었습니다.                                                                                                                                                          |

복제본의 이름을 Campaign 목록에서 `THE ASHEN PSALM — copy verified`로 변경하는 동작도 확인했습니다. Export/Import의 이번 UI 검증 경로는 JSON 표시 창과 붙여넣기입니다. 운영체제의 파일 다운로드 완료 이벤트는 이번 단계에서 별도로 검증하지 않았습니다.

### 화면 폭

각 폭에서 실제 화면을 확인하고 문서의 `scrollWidth`를 측정했습니다. 세로 스크롤바 폭을 제외한 문서 폭이 아래와 같으며, 가로 overflow는 없었습니다.

| 뷰포트 | 문서 폭 | 확인한 배치                                                                |
| ------ | ------- | -------------------------------------------------------------------------- |
| 360px  | 345px   | Campaign 목록, Dungeon Library, Room 3 편집. 한 열 및 긴 제목·버튼 줄바꿈. |
| 768px  | 753px   | Campaign 목록, 생성 설정, 던전 개요 한 열. 좁은 두 열 대신 한 열로 조정.   |
| 1440px | 1425px  | 던전 개요 두 열.                                                           |
| 3440px | 3425px  | 던전 개요 네 열, 각 열 약 638px.                                           |

Black Han Sans / 나눔스퀘어 네오와 기존의 넓은 한글 행간을 유지했습니다. 좁은 화면의 긴 방 이름도 여러 줄로 표시되도록 편집 필드를 조정했습니다.

### 자동 검사

기존 17개 테스트 파일은 삭제하거나 수정하지 않았습니다. `tests/campaign-structure.test.ts`에 12개를 추가해 총 29개가 개인 룰북 자료가 있는 환경에서 통과했습니다. 프로덕션 빌드·TypeScript·린트도 통과했습니다.

추가 검사는 v1 전체 저장 및 단일 던전 변환, 원문 백업, 숫자 ID의 UUID 변환과 반복 복원, 손상·미지원 자료 차단, 백업 쓰기 실패, 화면 이동과 수정 시각, 120개 던전, 전체 소유 ID 충돌 가져오기, 방 삭제·재굴림·직접 입력과 참조 안정성, Notes 분리, 일곱 지역의 철자, 지역 배율의 비중첩·단어 경계·양수 확률, 실제 원문 표 불변성을 다룹니다.

판별할 수 없는 과거 단일 던전 형식은 자동으로 추정하지 않으며 기존 저장 키에 원문을 보존합니다. 지원 범위와 저장 구조는 [Campaign 저장 구조](campaign-persistence.md)에 기록했습니다.
