# BMAD UX Calibration — 검색 취소와 키보드 복귀

2026-10-07 · 후속 관찰 및 최소 개입

작업 시작 시 이미 `ReferenceWorkbench.tsx`와 `publication.css`에 검색 개선이 있었다. 기존 [감사 보고서](ux-calibration-2026-10-07.md)와 그 변경을 보존하고, 현재 앱을 다시 관찰했다. **이번 제품 변경은 ReferenceWorkbench.tsx 한 파일의 검색 취소·포커스 연결이며 CSS 수정은 없다.**

## 1. Product Understanding

MÖRK BORG Reference Desk는 룰북과 종이 노트 옆의 규칙·오라클 참고집이다. 핵심은 검색/빠른 참조 → 원문 읽기 → 사용자가 명시적으로 굴리기 → 결과 복사 → 관련 규칙 확인이다. NPC는 일부 항목을 유지하며 재굴림하고, Mythic은 읽던 결과 위에서 독립적으로 열고 닫는다. 게임 진행을 자동으로 관리하는 흐름으로 바꾸지 않는다.

BMAD 설치를 확인하고 CIS Design Thinking의 SKILL.md, 전체 방법 CSV와 템플릿을 읽었다. Journey Mapping, 관찰과 추정을 구분한 Empathy Mapping, POV/How Might We, SCAMPER의 결합·적응·제거를 실제 관찰과 구현 선택에 적용했다. 16개 후보에서 두 개념만 구현하고 같은 브라우저 작업으로 검증했다. [방법 적용 기록](../_bmad-output/design-thinking-keyboard-return-2026-10-07.md).

실제 사람 인터뷰나 5–7명 사용자 연구는 하지 않았다. 아래는 에이전트가 실제 브라우저에서 수행한 결과이며 이용 빈도와 인지 비용은 전문가 판단이다.

## 3. Before Audit

소스 수정 전에 현재 빌드를 브라우저에서 직접 사용했다. 1440×900, 390×844를 기본 조건으로 삼았다. 기존 서버 4184에서 관찰했고 변경 후 같은 서버의 새 production build에서 재검사했다. 테스트 중 Vite 개발 포트 5187도 실행했다.

클릭 수는 지정한 시작 화면 이후 의미 있는 버튼 실행 수다. 텍스트 필드 focus는 클릭 수에서 제외하고 입력으로 별도 기록한다. 깊이 1은 홈에서 참조를 연 수준이다. 랜덤 내용 자체가 전후 같을 필요는 없으며, 같은 세션의 취소/Back에서는 결과 문자열의 완전 일치를 검사했다. Before의 Tab 4회는 첫 Tab의 실제 도착점(편의 동작)과 DOM의 포커스 가능 요소 순서로 계산했고, After 3회는 세 번의 Tab을 실제 누르며 각 도착점을 기록했다. Before 취소의 Tab·Enter는 기존 ×에 접근하는 키 경로이며 실제 취소 관찰은 × 클릭으로 수행했다.

| 작업 | 클릭 | 입력 / 키 | 최대 깊이 | 주요 화면 전환 | Back | 결과 뒤 다음 행동 |
| --- | ---: | --- | ---: | ---: | ---: | --- |
| 홈 → Reaction → ROLL → COPY → Morale | 4 | 0 | 1 | 2 | 0 | 복사 1클릭, 관련 규칙 1클릭 |
| `날씨` → Enter → R | 0 | 검색어 1회, Enter·R | 1 | 검색 목록·참조 2 | 0 | 정상적으로 명시적 굴림 |
| 홈 → NPC → ROLL → 이름 유지 → REROLL | 4 | 0 | 1 | 1 | 0 | 유지 후 재굴림 2클릭; Therg 유지 |
| 참조 → `없는항목XYZ` → 검색 취소 | 1 또는 0 | 검색어 1회; × 클릭 또는 Tab·Enter | 1 | 목록·원래 참조 2 | 0 | Esc 무반응; × 후 BODY focus |
| `날씨` → ArrowDown → Weather Enter → ROLL로 Tab | 0 | 검색어 1회, ArrowDown·Enter·Tab×4 | 1 | 목록·참조 2 | 0 | 선택 뒤 BODY focus; 편의 메뉴부터 다시 Tab |

추가 관찰: 모바일 FER 필터를 적용한 `날씨` 검색은 결과 1개다. `전체 보기`로 해제하면 검색어를 유지하고 8개 결과로 돌아온다. 필터 복구 문제라는 가설은 실제 관찰로 기각했다. COPY는 Weather의 `Cloudburst` 문자열까지 clipboard에서 확인했다.

증거: `outputs/ux-keyboard-return-20261007/before-escape.png`. 기존 감사 문서의 수치를 이번 신규 측정으로 사용하지 않았다.

## 4. Prioritized Problems

1–5 척도, 높을수록 부담/위험이 크다. 이용 빈도는 사용 통계가 아니다.

| 문제 | 분류 | 빈도 | 심각도 | 인지 비용 | 행동 비용 | 구현 위험 | 우선순위 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | --- |
| 검색창 Esc 무반응, × 후 읽기 포커스 단절 | A / C | 3 | 2 | 3 | 2 | 1 | MEDIUM |
| 결과 목록의 키보드 선택 후 BODY focus | C | 3 | 3 | 3 | 2 | 1 | MEDIUM |
| 필터 해제 시 검색어 유실 가설 | — | — | — | — | — | — | 재현되지 않음, 변경 제외 |
| 장식 제목·경계·간격에 대한 취향 변경 | — | — | 1 | 1 | 1 | 3 | LOW, 보류 |

새로운 HIGH 차단 문제는 대표 작업에서 발견하지 않았다. 이전 HIGH 검색 개선은 현재 정상 동작하므로 보존했다. 이번 MEDIUM 두 건은 같은 기존 포커스 경로를 재사용해 해결한다.

## 5. Changes

**검색 취소:** 검색창 Esc가 반응하지 않고 × 이후 BODY에 포커스가 남음 → 기존 `search('')`를 `clearSearch()`로 연결해 Esc와 ×가 함께 사용. 선택된 참조가 있으면 기존 제목으로 스크롤·포커스, 없으면 검색 입력으로 복귀 → 취소 2키가 1키로 줄고, 같은 결과를 다시 찾거나 굴릴 필요가 없다.

새 Escape 처리는 검색어가 있는 입력에만 적용하며 IME 조합 중에는 동작하지 않는다. 일반 Backspace로 입력을 지우는 기존 동작은 유지한다. ×의 기존 tooltip에 Esc를 안내한다.

**키보드 목록 선택:** 검색 입력에서 Enter는 제목에 포커스하지만 목록 행에서 Enter/Space는 BODY로 끊김 → 기존 목록의 키보드·보조기술 click(`detail=0`)에 기존 제목 포커스 플래그를 연결 → 두 경로의 읽기 시작점이 같아지고, Weather ROLL까지 Tab 4→3회. 목록의 명시적인 `굴리기`도 같은 제목 포커스를 사용한다.

포인터로 행을 여는 동작에는 이 포커스 분기를 추가하지 않았다. 새 컴포넌트·단축키 패널·저장 필드는 없다. 취소는 `activate`나 굴림 함수를 호출하지 않는다.

## 6. Preserved Elements

전체 색상·폰트·경계·spacing·레이아웃·정보 밀도·4개 주요 페이지·색인·필터·결과 항목 구조를 유지했다. 기존 CSS는 작업 전 사본과 byte 단위로 일치한다.

원문 자료, 주사위 공식, generator/domain/storage 코드, 저장 키, migration, 데이터 팩, package.json/lockfile, Vite 설정과 테스트 기대값은 수정하지 않았다. 작업 시작 전의 두 수정 파일과 untracked 문서를 삭제하거나 되돌리지 않았다.

## 8. Regression Check

- 시각 언어와 CSS 변경 없음. 기존 검색의 모바일 첫 결과 노출도 유지.
- 새 페이지나 중복 제어 없음. 기존 ×에 취소 키를 연결.
- 클릭 기반 빠른 참조와 NPC 흐름의 단계 증가 없음.
- 단순 열기/취소가 재굴림하지 않음. 전체 NPC 내용과 유지 상태 비교 통과.
- 0건 Enter, 모바일 필터의 전체 보기, 같은 검색어 재진입, R 명시 굴림 유지.
- Mythic 복귀와 browser Back 후 원래 결과 보존.
- 일반 포인터 선택의 포커스 경로를 변경하지 않음.
- 전체 1,233개 기존 검사로 자료·도메인·저장 관련 회귀를 확인했다. 새 저장 구조를 도입하지 않았다.

## 9. Remaining Problems

- 실기기 가상 키보드와 실제 한글 IME 조합은 검증하지 않았다. 코드의 composition guard와 실제 기기 검증은 구분한다.
- 스크린 리더 실제 낭독과 실제 사용자 5–7명의 사용성 연구는 미수행이다. DOM focus와 역할 기반 키보드 동작을 확인했다.
- Esc 취소는 검색 입력에 적용한다. 검색 결과 목록 전체를 새 keyboard navigation 위젯으로 바꾸지 않았다.
- 긴 표·결과의 내용량과 production의 기존 큰 chunk 경고는 이번 키보드 마찰의 범위 밖이다.
- iCloud 관리 폴더의 파일 로딩 지연이 개발·검사에 영향을 줬다. 사용자 파일·의존성 버전을 교체하지 않고 로컬 파일을 읽어 확인한 뒤 빌드와 실제 브라우저 검증을 수행했다.

Restraint test: 새 handler·focus 연결·기존 tooltip은 위 두 관찰 문제에 각각 대응한다. 시각 polish, navigation 교체, 신규 도메인 기능은 추가하지 않았다.
