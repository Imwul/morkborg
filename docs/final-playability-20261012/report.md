## E. Reliability Report

보관함에는 캐릭터1개와 서로 다른 시점에 저장한 던전2개를 두었다. 새 문서 로드 전후 각각 **실제로 렌더링된 본문**의 SHA256이 일치했다. 원본 저장 byte·전체 백업 파일까지 같다고 확장하지 않는다. 보관함을 닫아도 탐색 판정이 남았고, 새로고침 뒤에도 전투 HP5/Omen1 및 사기 메모와 Scratch 텍스트가 복원됐다. PIN2개와 Tray1개도 돌아왔다. 이후 QA 정리에서만 제거했다.

일반 생성 결과·하위표·판정 입력은 같은 문서 안의 임시 상태다. 새로고침 후 비워지는 것을 확인했다. 독립적인 보관함과 Scratch는 남았다. 발견한 방 수는 별도 노트에서 재입력했다. 이 수명 차이를 근거 없이 데이터 손실로 분류하거나 새로운 캠페인 저장 기능을 만들지 않았다.

COPY는 자연 던전에서 UI 성공 안내를 확인했고, 하위 결과 포함은 자동 검사와 실제 Scratch 텍스트로 확인했다. 마지막에는 Common 규칙의 COPY를 실행하고 **브라우저 세션의 클립보드**에서 해당 문구를 직접 읽어 일치를 확인했다. 운영체제 클립보드의 원래 내용이나 모든 기기의 클립보드까지 인증하지 않는다.

문서 전체의 불필요한 가로 스크롤·주요 요소 겹침은 관찰되지 않았다. 분류와 PIN 목록의 의도된 가로 스크롤은 있다. 작은 체크박스 표시 자체는 작지만 실제 라벨의 클릭 영역을 함께 검토했다. 실제 터치 제스처·휴대폰 키보드·Safari/Firefox·기기 확대는 미검증이다. 최종 수집한 브라우저 error 로그는0개다. 도구 선택자 오류·초기 로딩이 끝나기 전 시도는 앱 런타임 오류로 세지 않았다.

### SYS-18 / SYS-19 / SYS-20

SYS18/19의 기존 파일 왕복·검증·Undo 및 손상 보호 증거를 재사용했다. 이번에는 정상 저장/새로고침과 실제 위험 경로의 코드·기존 테스트를 검토했다. 손상된 저장소의 쓰기를 차단하는 guard와 원본 보존, 정상 저장 성공 뒤에만 cache를 바꾸는 순서, 업데이트의 CAS/원자성은 기존 보호다. 이미 검증된 장애를 다시 주입하거나 사용자의 저장소를 건드리지 않았다.

SYS20은 **PARTIAL 유지**다. 과거 실제 손상 byte/Quota 검사와 이번 정상 경로는 실제 IDB 거부·손상, localStorage 거부, offline/CAS의 모든 운영 환경을 대체하지 않는다. 현재 데이터 손실 결함은 재현되지 않았지만 영향이 큰 미검증 경계다.

QA 객체3개·PIN·Tray·Scratch·Last를 UI로 정리했고 전투는 새 전투의 기본 PC만 남겼다. 새 문서에서 Mythic 최근 판정0개와 임시 결과0개를 확인했다. viewport를 reset하고 QA 탭 및5532 서버를 종료했다. 독립 origin의 원문 cache와 원문 ID만 있는 탐색 최근 항목은 남을 수 있다. 이를 사용자 데이터 삭제를 위한 강제 저장소 초기화로 지우지 않았다.

## H. Final Product Assessment

**CONDITIONAL YES.** 별도 노트와 함께 Core+SD를 명시적으로 선택하고, 수동 HP·특수 DR·현재 발견 수를 관리하는 솔로 플레이에는 규칙 참조와 판정을 자연스럽게 이어갈 수 있다. 보관한 자료와 전투의 복귀는 관찰한 환경에서 안정적이었으며, 실제 정보를 잃는 이동·빠진 Scratch 내용·틀린 생물 원문 연결을 수정했다. 원문 출처와 선택적인 후속 절차를 구분한 채 플레이할 수 있다.

다만 원문 전체·모든 번역·실제 저장 장애·모든 기기 환경의 무조건적인 신뢰 보증은 아직 없다. 여러 장치 사이의 자동 기록 동기화도 이 제품의 이번 요구나 구현 범위가 아니다. 현재 플레이를 위해 앱이 이야기를 결정하거나 모든 오라클을 소비할 필요는 없다. 다음 유용한 검증은 인간의 실제 장기 플레이와 남은 특정 기기/저장 경계이며, FULL 비율을 올리기 위한 기능 추가는 필요하지 않다.
