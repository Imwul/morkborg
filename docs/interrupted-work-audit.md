# Interrupted-work follow-up — 2026-09-08

이전 요청, 중단 이후 커밋, 실제 공급 데이터, 현재 실행 화면을 대조했다. 처음부터 전부 완료되어 있지는 않았다. 화면용 번역 테스트와 실제 비공개 표 번역 커버리지가 달랐고, 새 Room 모델이 기존 Crawl 화면에 충분히 연결되지 않았다.

## 이미 반영되어 있던 요청

- FERETORY The Monster Approaches: A/B/C의 세 d12를 여러 능력치에 재사용한다. HP에는 원문이 별도로 요구하는 굴림이 있다. '모든 난수 호출이 세 번'이라는 의미는 아니다.
- 캐릭터의 과거와 버릇은 각 한 번이다. Terrible Traits 두 번과 구별된다.
- 던전마다 Common 6칸 / Rare 6칸을 고정 유지한다. 방 이동이나 조우 굴림이 해당 목록을 새로 만들지 않는다.
- Special Room 준비는 네 칸. Strong은 다음 Special, Weak는 일반 방, Miss는 위험 해결 후 일반 방이다. 방 해결 후에만 다음 Crawl을 굴린다.
- 의미 없는 장식 문양 제거, 몬스터·방의 시각 묶음, 9개 출처 약칭과 사이트 하단 한 줄 범례가 존재한다.
- 여행은 새벽/달력 → 날씨 → 도로 또는 채집 → 필요한 이동·야생 판정 → 조우 해결 → 야영으로 연결된다. 같은 날 중복 새벽·정착지 발견 굴림을 막는다.
- 정착지 발견은 AitC PDF 5 / 인쇄 3의 여행일당 1/8이다. 항상 도시라는 뜻은 아니다.
- NPC 생성과 도시 NPC 조우는 서로 다른 도구다. 길 묻기·기도·물건 숨기기, Microcrawl/City Crawl의 Strong/Weak/Miss 절차가 존재한다.
- 검색·핀·최근·복사·출처·한국어 도움말은 Campaign 선택 없이도 사용할 수 있다. 기록 기능은 보조 기능으로 유지한다.

## 나중 지시에 따라 달라진 요청

- '던전 이름·지역에 어울리는 특별한 방 문장'은 이후의 출처 순수성 지시로 대체됐다. 원문 조각을 제공하며 분위기 연결 문장이나 임의 역할을 다시 넣지 않는다.
- FER 인쇄 7쪽의 Leaving the Road는 야생 진입 때의 표다. 모든 여행/채집 후 무조건 별도 조우를 추가하지 않는다.
- Depths 인쇄 7쪽은 적·장애물 처리다. 야영의 주요 출처는 SD PDF 8 / 인쇄 6과 FER PDF 9 / 인쇄 7이다.
- 원문에서 제공하지 않는 몬스터 능력치 및 충돌 규칙은 빈 값/출처 경고로 남긴다. 이는 중단된 구현과 다르며 [8개 원문 문제 목록](product-integrity/FINAL-REPORT.md#남겨-둔-원문-문제)을 유지한다.

## 공개 사이트 확인 범위

`https://morkborg-4e3y.vercel.app/`를 새 Chromium 저장소에서 열고 세 번 다시 불러왔다. 모두 HTTP 200, 동일한 앱 제목과 동일한 index asset이었다. 페이지 오류 0, Service Worker 등록 0, HTML 캐시는 `max-age=0, must-revalidate`였다. 이전 사이트가 잠깐 보이는 현상은 이번 점검에서 재현되지 않았다. 기존 사용자의 오래 열린 탭이나 폰트 전환까지 모두 해결됐다고 단정하지 않는다.

점검 시 원격 main은 `f6da8185d8f4be49b6f1de9ac5e08a3a7571ff14`, 로컬 직전 커밋은 `ca26155032e02c27b21ad8c83d2aa2287a2d0421`이었다. 원격 branch SHA를 실제 배포 SHA로 간주하지 않는다. 이번 작업은 로컬 수정·검증·커밋이며 push와 배포를 하지 않는다.

## 검증과 데이터 보존

- 실제 사용자 저장소와 분리된 Chromium 프로필에 `INTERRUPTED WORK QA` 캠페인을 UI로 생성했다. 기존 사용자 캠페인을 재굴림하거나 정리하지 않았다.
- Sarkash 던전과 특별한 방 네 개를 만들고 Crawl 준비 목록에서 직접 열었다. 방 이름 편집 후 구성 요소 재굴림, 다른 방 불변, 출처의 수동 수정 표시, 재로드 보존을 확인했다.
- Weak 일반 방 → 방 해결 → Miss → 위험 해결 → 일반 방 진입을 실제 UI에서 검사했다. 필요한 분기는 QA 프로필에 한해 주사위 입력을 고정했고 즉시 원래 난수 함수를 복원했다. 위험 해결은 Crawl 주사위를 다시 굴리지 않는다.
- 새 일반 방에서 adjective를 직접 수정하고 type만 다시 굴렸다. 수동 adjective는 유지되고 파생 제목·출처가 함께 갱신됐다. 중복 제목은 기본 카드에서 사라졌다. 출처에서 정규 표를 열어 실제 행을 보고, 닫으면 같은 방으로 돌아왔다.
- 실제 AitC 데이터로 거리와 NPC 조우를 생성했다. `Filthy`/`Plaza/Square`/`NPC Encounter`, 도박꾼 조우의 수량과 조건, 기도 실패 결과에 별도 한국어가 표시됐다. 영문 복사, NPC 조우 핀, 현재 거리·핀·캠페인의 재로드 보존을 확인했다. 여관 그룹의 Three Dead Skulls도 실제 참조를 열었다.
- 별도 빈 브라우저에서 library 요청과 서버 자료 요청을 404로 만들고 Oracle 359표만 공급했다. Library가 실제로 없음을 확인한 뒤 물건 회수 Weak의 NPC 분기를 선택했다. 원문과 한국어는 보존되고 `SOURCE DATA UNAVAILABLE: sd.npc.disposition, sd.npc.profession`이 표시됐다. 페이지 오류는 0개였다.
- 360/768/1440/3440에서 입구, 준비 방, 현재 방, City 결과를 캡처하고 실제 이미지를 읽었다. 위험 대기 화면도 같은 네 너비에서 캡처했다. 가로 문서 넘침은 없었으며 큰 화면은 내용 폭이 제한된다. 360에서는 출처를 펼쳤을 때 텍스트·표 열기 버튼이 정상적으로 줄바꿈된다.
- 원래 '잘리네' 첨부 이미지가 하단 출처 범례임을 직접 확인했다. 현재 범례는 44px 높이 안에서 텍스트 하단이 17px 지점에 있어 스크롤바와 분리된다. 네 너비에서 한 줄과 가로 스크롤을 확인했고, 휴대폰에서 페이지 끝까지 내리면 고정 도구와 겹치지 않는다.
- 비공개 데이터는 수정 전 bundle·설정·manifest·fixture를 `outputs/aitc-before-translation/`에 백업했다. 이전 캠페인 백업도 유지했다. 영어·ID·주사위·범위의 SHA256은 불변이다. 같은 키로 로컬 암호문만 준비했으며 복호화한 내용이 의도한 payload와 일치한다. 평문 자료와 전체 번역표는 커밋하지 않는다.
- 번역 상세 및 기계 판독 집계: [City 후속 보고서](product-integrity/prior-city-travel-followup.md), [번역 커버리지 JSON](product-integrity/aitc-translation-coverage.json).

최종 전체 테스트는 **532/532 통과**, 실패·취소·skip 0이다. 직전 509개에서 신규 회귀 23개를 추가했다. `npm run lint`, client/server TypeScript, production build, 공개 빌드 privacy 검사(70 static files), `git diff --check`도 모두 통과했다.

첫 전체 검사에서 최신 private fixture를 쓰며 기존 300개/503개 기대값과 부분 가져오기의 실제 책 간 참조 오류가 드러났다. 최신 359개/562개 수 및 정확한 ID 집합을 검증하도록 고쳤고, fetch mock은 assertion 실패에도 정리하게 했다. 고유명사 72개 및 새 번역 메타데이터만 명시적으로 구별하고 원문·규칙·가중치·사용자 추가 데이터의 완전 동등성 검증은 유지했다. 잘못된 ID와 위조/변경된 원문을 거부하는 회귀, 선택된 의존성만 검사하는 회귀, 수동 제목·구성 요소·번역의 보존 회귀를 추가했다.

이번 점검에서 발견한 구현 누락은 처리했다. 여전히 별도로 남는 것은 원문 자체의 누락·충돌, 재현되지 않은 오래된 탭의 화면 전환 현상, 그리고 수행하지 않은 공개 push/배포다. 이를 구현 완료와 혼동하지 않는다. 정확한 최종 로컬 커밋 해시는 전달 응답에 기록한다.
