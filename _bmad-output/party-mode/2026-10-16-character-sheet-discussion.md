# 캐릭터 시트: 생성식·맥락·시작 축복 토의

2026-10-16 · BMAD `bmad-party-mode` · 사용자 요청: 여러 차례 토의 후 자율 구현·검증·푸시.

설치된 SKILL.md, 커스터마이징, party-memory 지침을 읽고 프로젝트 config/customization 및 party resolver를 실행했다. 기본 installed 룸과 이후 `code-review-crew` 룸 모두 설정된 session 모드(인라인 페르소나 토의)로 진행했다. 구현·원문 검토를 병렬 수행한 실제 보조 에이전트는 이 페르소나들과 별개다.

## 1. 값과 생성식의 거리

🎨 **Maya:** “값은 위에 있고 생성식은 아래에 있으면 플레이어가 같은 정보를 찾으러 왕복합니다.”

🔬 **Dr. Quinn:** “생성 주사위와 실제 판정에 쓰는 보정치를 구분해야 합니다. Pale One의 +1은 3d6 총합에 더하는 수치가 아닙니다.”

🎬 **Caravaggio:** “수치 아래 작은 ‘생성:’ 줄을 두죠. 큰 숫자의 우선순위는 그대로 두고요.”

📖 **Sophia:** “아이템 이름만으로는 왜 가진 건지 모르죠. 공통 장비인지 직업 능력에서 온 물건인지도 붙여야 합니다.”

구현 기준: 실제 생성 provenance로 증명되는 공식만 표시하고, 아래에서는 그 중복 문장만 제거한다. 장비 맥락도 출처로 증명되는 범위만 붙인다.

## 2. 축복의 조건과 원문 충돌

🔬 **Dr. Quinn:** “다섯 축복을 발견했다고 다섯 개의 공짜 보상을 주면 안 됩니다. 죽은 캐릭터의 유산은 조건이 있습니다.”

🎨 **Maya:** “당장 바뀌는 HP와 나중에 적용하는 조건부 혜택이 화면에서 구별돼야 해요.”

🎬 **Caravaggio:** “즉시 바뀌는 HP는 상단 값과 생성식을 함께 교체합시다.”

PDF13 ‘하나 이상’과 PDF18 ‘하나’ 차이를 화면에 알리고, 상세 규칙을 따라 선택을 허용한다. 기본 OFF, Enhanced Fortitude만 즉시 수치에 적용하고 나머지 효과는 조건·대가를 읽게 한다.

## 3. 기존 캐릭터와 복원

🔬 **Dr. Quinn:** “시작 HP 대체에 체력 보정치를 더하면 안 됩니다. 상속 축복도 사망 조건 없이 보상을 주면 규칙이 달라집니다.”

🎨 **Maya:** “선택을 바꿨을 때 기존 캐릭터가 바뀌는지, 다음 생성에 적용되는지 분명해야 합니다.”

🎬 **Caravaggio:** “공식은 수치 바로 아래에 작게 두고, 아래 설명에는 직업의 특징과 제약을 남기는 편이 읽기 좋습니다.”

구현 기준: 변경 예정 안내, 생성 시 한 번만 적용, 과거 Last/Replay의 누락 설정을 현재 설정으로 대체하지 않음. 저장 데이터 구조는 기존 optional 매개변수만 확장한다.

## 4. Code Review Crew 후속 룸

🔒 **Vex:** “개인 자료 식별자와 겹치는 직업명을 코드에 직접 넣은 부분이 빌드를 막고 있습니다.”

🎯 **Yui:** “그 직업의 원문 규칙에 이미 ‘일일 파워 소모’가 명시돼 있습니다. 그 근거로 기존 횟수를 표시합시다.”

🌶️ **Boundary:** “과거 저장에 축복 설정이 없는 경우도 확인해야 합니다. 현재 화면의 선택을 물려받으면 안 됩니다.”

🚢 **Dana:** “조건 확인이 필요한 축복은 효과와 대가를 읽게 하고, 새 캠페인 관리 기능까지 늘리지는 맙시다.”

실제 조치: 개인 자료 경계 검사는 유지하고 직업명 직접 비교를 원문 규칙에 따른 표시로 교체. 미선택 과거 저장 오염 재현2건에 회귀 검증을 추가했다. 브라우저의 맥락 문구 CSS 충돌도 확인·수정했다. on_complete resolver는 두 룸 종료 시 모두 빈 문자열이라 추가 실행 지시가 없었다.

최종 결과·원문 근거·실제 브라우저 및 자동 검증은 `docs/character-sheet-20261016/report.md`를 따른다. 개인 메모리 로그와 원문 PDF는 이 산출물에 포함하지 않는다.
