# Design Thinking Session: Translation & Character Reading

**Date:** 2026-10-16 · **Facilitator:** Codex · **Design Challenge:** 한국어로 규칙을 읽고 캐릭터를 확인하는 흐름 개선

## Design Challenge

사용자는 전체 번역 개선, 캐릭터 시트의 줄바꿈·레이아웃 수정, 오멘·권능 횟수의 작은 안내를 요청했고 수정·검증·푸시까지 자율 진행하도록 지시했다. 기존 Reference Desk 구조·원문·확률·저장 자료를 보존한다. 사용자 지시에 따라 단계별 승인 질문은 생략한다.

## EMPATHIZE: Understanding Users

### User Insights

사용자 발언과 기존 UX 원칙을 근거로 한다. 인터뷰·5–7명 사용자 연구는 수행하지 않는다. Journey Mapping, Empathy Mapping, Shadowing의 관찰 항목을 에이전트의 실제 브라우저 점검에 적용한다. 실제 사람을 관찰했다고 주장하지 않는다.

### Key Observations

독립 origin 127.0.0.1:5533에서 캐릭터 → 직업 선택 → 이단 사제 생성 → 보관 → 비전의 은둔자 생성. 360×800의 실제 innerWidth/Height 및 visualViewport345×800 확인, 가로 넘침 없음. 사제 규칙에 ‘지각는’, ‘근력는’, ‘권능를’이 실제 표시됨. 시트 Toughness ‘강인함’, 본문 ‘체력’, 직업 요약 ‘건강’ 혼용. 무직·무작위 직업·능력치 선택 설정에 영어만 남음. 오멘 수치와 권능 하루 사용 횟수는 있으나 회복·차감 조건이 그 옆에 없음.

### Empathy Map Summary

말함: 번역·줄바꿈을 고치고 횟수를 안내해 달라. 행동: 직업 선택, 수치 읽기, 긴 능력 읽기, 보관·복귀. 필요: 같은 능력치라는 확신, 숫자와 조건을 함께 확인. 추정: 번역 조사를 해석하고 회복 규칙을 따로 찾는 일이 읽기를 방해할 수 있음. 감정·시간·실사용 빈도는 측정하지 않음.

## DEFINE: Frame the Problem

### Point of View Statement

한국어로 솔로 플레이하는 사용자는 원문과 대응하는 일관된 용어, 읽기 쉬운 시트, 수치 가까이의 횟수 안내가 필요하다. 같은 능력치를 여러 이름으로 표시하거나 지침 없이 횟수만 보여 주면 판단에 불필요한 추론이 필요하기 때문이다.

### How Might We Questions

어떻게 원문을 바꾸지 않고 조사와 확정된 용어를 고칠까? 어떻게 기존 시트를 유지하면서 한글과 영문 라벨을 안정적으로 줄바꿈할까? 어떻게 직업 능력과 두루마리의 횟수 규칙을 혼동시키지 않을까?

### Key Insights

확정 번역과 표시 단계부터 교정한다. ‘Power’라는 글자만으로 모든 직업 능력에 Core 사용량을 적용해서는 안 된다. 캐릭터 데이터와 편의 생성·재굴림은 실제 휴식/소비 규칙과 별개다.

## IDEATE: Generate Solutions

### Selected Methods

SCAMPER의 수정·결합·적응 관점과 Brainstorming, Affinity Clustering으로 아래 후보를 비교했다.

### Generated Ideas

1. 능력치 영어 치환 후 조사 교정. 2. 원문 문맥을 표시 helper에 전달. 3. 체력 용어 통일. 4. 오멘 용어 통일. 5. 생성 모드 한글 병기. 6. 기존 직업 번역을 선택 목록에 병기. 7. 능력 선택 옵션 한글 병기. 8. 날씨·사냥·가능성 설정 번역. 9. 전투 입력 능력명 번역. 10. 능력치 제목의 영·한 줄 분리. 11. 긴 한글 단어의 불필요한 분절 방지. 12. 오멘 회복 안내를 수치 아래 표시. 13. 권능 성공 시 차감을 하루 횟수 옆에 표시. 14. 기존 상세 규칙으로 연결. 15. 직업 능력의 독립 횟수 예외 명시. 16. 새 자원 추적 패널. 17. 모든 원본 번역 재작성. 18. 저장된 개인 텍스트 일괄 변환.

### Top Concepts

확정된 공통 번역 교정 + 기존 입력 라벨 병기 + 시트 줄바꿈·작은 문맥 안내를 선택한다. 새 패널, 번역 전체 재작성, 개인 저장문 변환은 변경 위험·범위 때문에 제외한다.

## PROTOTYPE: Make Ideas Tangible

### Prototype Approach

기존 컴포넌트에 직접 작은 변경을 적용하고 동일한 생성 결과를 다시 읽는 Role Playing/Assumption Testing을 수행한다. 스타일 시안만으로 완료하지 않는다.

### Prototype Description

원문·주사위·사용자 입력·저장 스키마를 유지하며 표시 텍스트와 캐릭터 읽기 배치를 수정한다. Core BBE34·37, FERETORY 직업별 횟수 예외를 원문으로 확인했다.

### Key Features to Test

잘못된 조사와 두루마리 용어, 수치 보존, 설정 value 유지, 직업별 횟수 구분, 능력치/긴 문장 줄바꿈, 안내→원문→같은 결과 복귀, 보관·재로드, 좁은/중간/넓은 실제 viewport.

## TEST: Validate with Users

### Testing Plan

독립 QA 자료로 에이전트 브라우저 점검 및 관련 회귀·전체 자동 검사를 수행한다. 실제 사용자 연구와 구분한다. 변경 전 캡처는 outputs/translation-layout-20261016에 보존한다.

### User Feedback

새로운 사용자 피드백은 없다. 에이전트의 실제 브라우저 검증: 사제의 잘못된 조사 제거, 은둔자 두 자원 안내 표시, 안내→원문→Back에서 전체 결과 동일, 보관한 원문·번역 2,166자의 새로고침 전후 동일을 확인했다. 조건별 권능 판정은 보정2+d4=3→5로 기존 계산을 유지했다. production preview에서도 함정5번의 오멘/지각 교정과 캐릭터 안내를 직접 확인했다.

### Key Learnings

같은 Vrakh 결과로 네 실제 viewport의 가로 넘침이 없었다. 능력치 라벨은 약21.8px에서 두 줄 약43.3px로 커졌으며 읽기 배치를 일정하게 하는 대신 높이를 조금 사용한다. 새 안내의 CSS 우선순위로 아래 간격이 누락된 것을 최종 화면에서 확인해 보정했고 production에서 24px 간격과 네 viewport를 다시 확인했다. 일반 건강·전조와 수치가 보존되도록 원문 문맥을 한정해야 한다. 클립보드 API 빈 응답은 검증 완료로 처리하지 않았다. 최종 전체 자동 검사 1,277개·타입·lint·production build 통과. 브라우저 error 기록0. 실제 사람의 이해도나 완료 시간은 측정하지 않았다.

## Next Steps

### Refinements Needed

선택한 개입을 구현·검증했다. 새 패널·자원 자동 추적·저장 텍스트 변환 없이 기존 읽기 흐름을 유지한다. 전체 문장 의미 검수와 다른 실제 기기는 후속 검토 범위로 남긴다.

### Action Items

화면 재검증·관련/전체 검사·결과 문서 완료. QA 보관 캐릭터2개를 정리했고 생성한 브라우저 탭과 서버를 종료했다. 원문/개인 팩과 전체 증거는 ignored 경로에 보존한다. 빌드 뒤 순차 실행한 공개/개인 자료 및 Git 경계 검사 통과. 완료 resolver도 실제 실행해 빈 workflow.on_complete를 확인했다. 최종 기록을 커밋·푸시한다.

### Success Metrics

확인된 오역/조사 오류 제거, 능력치 라벨 안정적 줄바꿈, 실제 viewport의 가로 넘침 없음, 올바른 회복·소모 조건 표시, 현재 결과·보관 자료 보존. 테스트 개수나 BMAD Trace 점수를 번역의 완전성 지표로 삼지 않는다.
