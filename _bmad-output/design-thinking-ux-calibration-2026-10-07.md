# Design Thinking Session: MÖRK BORG Reference Desk

**Date:** 2026-10-07, Asia/Seoul
**Facilitator:** Codex
**Design Challenge:** Preserve the identity. Reduce the friction.

## Design Challenge

종이 노트와 룰북을 사용하는 플레이어가 규칙을 찾고, 독립적인 굴림을 실행하고, 결과를 복사하거나 관련 참조로 이동하는 과정에서 발생하는 실제 마찰을 줄인다. 기존 서체, 색상, 출처 체계, 주요 페이지, 저장 형식과 룰 계산은 보호한다.

사용자 제공 UX Calibration 전문을 사전 입력으로 읽었다. 설치된 사용자 스킬 루트와 프로젝트를 확인하고 `bmad/scripts/knowledge.py --content`로 설치 상태를 확인했다. BMAD CIS Design Thinking의 SKILL.md, customize.toml, design-methods.csv 전체, template.md를 읽고 프로젝트의 resolve_customization.py와 resolve_config.py를 실행했다. 설치된 CIS에는 Design Thinking이 있으며, 별도 소프트웨어 UX/UI·Product Design·Critique 스킬을 사용했다고 주장하지 않는다. 사용자가 중간 승인 없이 완료하도록 요청했으므로 스킬의 대화형 체크포인트를 자동 진행했다.

## EMPATHIZE: Understanding Users

### User Insights

방법: Journey Mapping, 실제 UI를 통한 작업 역할 수행, 관찰 근거와 추정의 분리. 실제 사람의 인터뷰·Shadowing·감정 데이터는 수집하지 않았다. 사용 빈도는 제품의 핵심 작업에 근거한 가설이며 실제 이용 통계는 아니다.

주요 작업:

1. 홈 → Reaction → ROLL → COPY → Morale. 4클릭, 입력 0회, 페이지 전환 2회, Back 0회. 복사 완료와 기존 관련 참조를 직접 확인했다.
2. 참조 검색에 `날씨` 입력 → Enter → Weather → 굴리기 → COPY. 입력 1회, Enter 1회, 굴리기·복사 2클릭. 모바일에서도 같은 검색을 실행했다.
3. 생성기 → NPC → ROLL → 이름 유지 → REROLL. 5클릭, 입력 0회, 페이지 전환 2회. 이름 Karva가 유지되고 나머지 항목이 변경되는 것을 확인했다.
4. 기존 NPC → Mythic → ROLL FATE → 닫기. 3클릭, 필수 입력·페이지 전환·Back 0회. 같은 NPC로 복귀했다.

### Key Observations

- 1440×900 홈에는 장식 워드마크와 장식 서체의 빠른 참조, 노란 생성기 영역이 있다. 참조 화면은 좌측 색인과 읽기 영역을 유지하며 ROLL과 COPY가 분리돼 있다.
- 390×844, 홈에서 `날씨` 검색: scrollY 0, 헤더 높이 220px, 탐색 패널 높이 810.95px, 첫 Weather 결과 상단 1191.22px. 실제 화면에는 검색 결과 대신 기존 테마별 탐색 목록이 보인다. 가로 넘침은 없다.
- 기존 참조가 열린 상태에서 `zzzz없는참조` 입력 후 Enter: 0건 안내가 사라지고 이전 Reaction으로 돌아간다. 검색창에는 실패한 검색어가 남는다.
- Enter로 Weather를 열어도 검색창이 포커스를 유지한다. R을 누르면 굴림 대신 검색어 `날씨r`과 0건 결과가 생긴다.
- Weather를 연 뒤 ⌘K: 검색창에는 `날씨`가 있지만 결과 목록은 열리지 않는다. 같은 결과를 다시 보려면 검색어를 편집해야 한다.

### Empathy Map Summary

Do: 규칙 확인, 디지털 굴림, 복사, 개별 항목 유지, 필요할 때 Fate 판정.
Need: 읽던 결과를 기억하거나 홈으로 반복 복귀하지 않고 검색과 판정을 이어가기.
Think/Feel: 실제 사람 자료가 없으므로 단정하지 않는다. 결과가 화면 아래에 있고 입력 초점과 화면 목적이 어긋나는 동작만 확인했다.

## DEFINE: Frame the Problem

### Point of View Statement

플레이 중 참조를 찾는 사용자는 검색 직후 일치 결과와 다음 실행 대상을 확인할 수 있어야 한다. 현재 모바일 검색은 탐색용 목록을 결과보다 먼저 보여주고, 키보드 검색은 참조를 연 뒤에도 입력 초점과 결과 화면이 어긋나기 때문이다.

### How Might We Questions

- 검색 중에도 기존 필터를 유지하면서 일치 결과를 첫 화면에 보여줄 수 있는가?
- 결과가 없을 때 실행한 Enter가 읽던 참조와 실패 상태를 혼동시키지 않게 할 수 있는가?
- 기존 R 단축키와 ⌘K를 검색 후에도 추가 입력 없이 사용할 수 있는가?

### Key Insights

문제는 새로운 검색 기능이나 전체 내비게이션 부재가 아니라 결과 표시와 필터 확장 상태의 결합, 제출 시 무조건 닫는 처리, 참조를 연 뒤 남는 입력 포커스다. 데이터와 룰 엔진을 변경할 이유가 없다.

## IDEATE: Generate Solutions

### Selected Methods

SCAMPER의 Combine / Eliminate / Adapt와 Problem Framing. 각 문제의 기존 요소를 연결하거나 덜 노출하는 방안을 먼저 비교했다.

| 3. 검색 결과를 페이지 상단의 별도 모달로 표시 | 제외: 현재 읽기 구조를 대체한다 |

### Top Concepts

1. 결과를 가리지 않는 모바일 검색: 기존 필터 재사용, 검색 동안만 무관한 탐색 축소.
2. 결과가 없는 검색의 제출은 화면을 유지.
3. 키보드 제출과 검색 재진입의 포커스·결과 상태 연결.

## PROTOTYPE: Make Ideas Tangible

### Prototype Approach

실제 앱에서 기존 컴포넌트를 수정하는 작은 기능 프로토타입. 별도 디자인 시안이나 새 화면을 만들지 않는다.

### Prototype Description

ReferenceWorkbench.tsx에서 검색 결과 표시와 모바일 필터 확장을 분리한다. Enter로 열 때만 기존 제목을 포커스한다. 검색창 재진입으로 기존 결과를 다시 연다. publication.css의 모바일 조건에서 검색 중 무관한 탐색을 숨긴다.

### Key Features to Test

동일한 390×844 검색, 1440×900 키보드 경로, 실패 검색의 Enter, 모바일 필터 재확장, 같은 검색어 재진입, 기존 Reaction·NPC 유지/재굴림·Mythic 복귀. 저장과 룰 코드의 변경이 없는지 비교한다.

## TEST: Validate with Users

### Testing Plan

CUA 실제 브라우저로 같은 작업을 전후 수행하고 DOM 위치·포커스·결과를 측정한다. 360 / 390 / 768 / 1440px에서 가로 넘침과 필터 접근을 확인한다. 기존 자동 검사, 타입 검사와 정적 빌드를 수행한다. 실제 사람 5–7명의 사용성 연구는 이번 작업에서 수행하지 않는다.

### User Feedback

사용자 인터뷰 피드백 없음. 위 관찰은 에이전트의 브라우저 직접 사용 결과다. 검증 결과는 아래의 최종 결과와 docs/ux-calibration-2026-10-07.md에 기록한다.

### Key Learnings

- 같은 390×844 검색에서 첫 Weather 결과 y는 1191.22px에서 441.27px로, 탐색 패널 높이는 810.95px에서 61px로 줄었다. 첫 결과 확인에 추가 스크롤 0회다.
- 360 / 390 / 768 / 1440px에서 검색·Weather 열기·재굴림·복사를 수행했고 가로 넘침이 없었다. 출처 필터의 접근과 접힌 상태의 적용 필터명 표시를 확인했다.
- 검색 → Enter → R은 제목 포커스 뒤 기존 굴림을 실행하며 검색어를 바꾸지 않는다. ⌘K 재진입은 추가 텍스트 편집 0회이며, 0건 Enter는 실패 안내와 검색어를 유지한다.
- Reaction·COPY·Morale 4클릭, NPC·굴림·이름 유지·재굴림 5클릭, Mythic·판정·닫기 3클릭은 동일했다. 이름 유지와 Mythic 복귀, Back에서 같은 결과 복원, PIN 새로고침 유지도 확인했다.
- 첫 전체 자동 검사는 1233개 모두 통과했다. 기존 lockfile의 정확한 버전으로 복원한 최종 전체 검사는 1205개 통과와 JSON 빈 내용으로 인한 2개 파일 초기화 실패를 기록했다. 자료 내용 확인 후 해당 두 파일의 28개 테스트를 모두 통과했다. 최종 환경에서 1233개 개별 테스트가 검증됐다. lint, 클라이언트·서버 타입 검사, production build와 공개·private boundary 검사도 통과했다.
- 최종 production preview의 모바일 좌표와 키보드·0건 검색 동작은 개발 서버 관찰과 같았다. 이 최종 브라우저 검증에서 error 로그는 0개였다.
- 실제 사람의 완료 시간이나 심리적 만족도를 측정하지 않았다. 인지 비용 감소의 근거는 일치 결과가 첫 화면에 보이고, 검색 실패 상태가 유지되며, 같은 검색어를 기억해 다시 편집할 필요가 없어진 동작이다.

## Next Steps

### Refinements Needed

측정한 검색 마찰만 변경했고, 기존의 빠른 참조·독립 굴림·개별 유지·Fate 복귀를 보호했다. Escape 취소와 실기기 가상 키보드, 실제 사람 사용성 연구는 남은 과제다.

### Action Items

구현, 동일 작업 재수행, 모바일 필터·포커스 회귀 점검, 검사 기록 저장, 9개 항목 순서의 보고서를 완료했다. 기록: docs/ux-calibration-2026-10-07.md 및 outputs/ux-calibration-20261007/. 코드 변경은 ReferenceWorkbench.tsx와 publication.css 두 파일이다.

### Success Metrics

정의한 다섯 기준을 모두 충족했다: 첫 모바일 일치 결과가 화면에 보이며 추가 스크롤 0회, 실패한 Enter가 기존 참조로 전환하지 않음, Enter 이후 R이 검색어 변경 없이 기존 굴림 실행, 같은 검색어 재진입에서 추가 편집 0회, 보호 대상 작업의 클릭 수와 결과 유지 동작 유지.
